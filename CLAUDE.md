# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is the **documentation website** for NOMAD (NMR Online Management And Datastore), not the NOMAD application itself. It is a Docusaurus 3 static site published at https://nomad-nmr.netlify.app. The actual application lives in separate repositories: `nomad-nmr/nomad-server` (contains `nomad-front-end` React SPA + `nomad-rest-api` Express/MongoDB back end) and `nomad-nmr/nomad-spect-client` (Node.js client running on spectrometer PCs, talking to Bruker IconNMR). Content changes here document that system; they do not change it.

## Commands

Yarn is the package manager (`nodeLinker: node-modules`, Yarn Berry via `.yarn/`). There are no tests, linter, or type checking configured — a successful `yarn build` is the verification step.

- `yarn` — install dependencies
- `yarn start` — dev server with hot reload
- `yarn build` — production build into `build/` (fails on MDX/React errors; broken links only warn, see `onBrokenLinks: 'warn'`)
- `yarn serve` — serve the production build locally
- `yarn clear` — clear the `.docusaurus` cache when the dev server behaves oddly after config or content moves

## Content structure

- `docs/` — the documentation sidebar, autogenerated from the filesystem (`sidebars.js` uses a single `autogenerated` sidebar over `docs/`). Ordering is therefore controlled entirely by `sidebar_position` in each file's front matter and by `_category_.json` in subfolders (`docs/getting-started/_category_.json` sets its label and position). Adding a doc without `sidebar_position` puts it in an arbitrary place.
- `docs/getting-started/` — the installation/configuration path: server installation → IconNMR configuration → spectrometer client installation → NOMAD configuration → for-developers. These docs cross-reference each other with relative links plus anchors (e.g. `./client-installation/#config`); keep those in sync when renaming headings.
- `docs/video-tutorials.mdx` — MDX page importing `Gallery` from `docs/video-gallery.js` (a React component that lives inside `docs/`, not `src/`). Videos are passed as parallel `links`/`titles` arrays.
- `blog/` — release announcements and feature posts; either a flat `.md` file or a dated folder with `index.md` plus its images. Authors are defined in `blog/authors.yml`.
- Doc images live next to the docs that use them (`docs/assets/`, `docs/getting-started/assets/`), while site-wide images and SVGs live in `static/img/`.

## Homepage

`src/pages/index.js` composes the landing page from components in `src/components/`, each with a CSS module beside it. Two content lists are edited directly in JS rather than in markdown:

- `HomepageFeatures.js` — the feature matrix. Each bullet is tagged with either `styles.featureImplemented` or `styles.featurePlanned`; the legend rendered in `index.js` depends on that distinction, so use the correct class when adding a feature.
- `TestimonialsCarousel.js` — the quote/author array driving the carousel.

`index.js` also contains a demo-server modal (credentials and the `demo.nomad-nmr.uk` link) that is currently gated behind `showModal`, whose toggle is passed to the header but not wired to a button.

## Conventions

Source files use no semicolons, single quotes, and 2-space indent (Prettier-style, but no Prettier config is committed — match the surrounding file). Prose is **British English** (`.vscode/settings.json` sets `cSpell.language` to `en-GB`). Documentation prose bolds external links, e.g. `**[NMRium](https://www.nmrium.org/)**`, and uses Docusaurus admonitions (`:::tip`, `:::note`) for callouts.
